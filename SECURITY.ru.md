# Политика безопасности

[English](SECURITY.md)

Для развёртывания RadixDB необходим внешний план резервного копирования,
восстановления и действий при отказе, проверенный на собственной нагрузке.
Принятое release evidence записано в [истории изменений](CHANGELOG.ru.md).

## Сообщение об уязвимости

Для чувствительных проблем используйте private vulnerability reporting GitHub,
если он включён в репозитории. Если канал ещё не включён, свяжитесь с
maintainers непублично и не размещайте детали эксплуатации в открытом issue.

Публичные GitHub issues подходят для нечувствительных ошибок, дефектов
документации и воспроизводимых падений, которые не раскрывают слабость
безопасности.

В сообщении укажите:

- версию RadixDB и commit hash;
- операционную систему и архитектуру CPU;
- затрагивает ли проблема embedded, CLI или TCP server mode;
- минимальный SQL/script/configuration для воспроизведения;
- подозревается ли corruption данных, раскрытие данных или denial of service.

## Поддерживаемые версии

В сообщении указывайте точный выпуск и commit. Текущий принятый выпуск — 1.1.0.
Эта политика не обещает срок security support или автоматические backports на
старые revisions; решение о поддержке записывается для каждого выпуска.

## Границы применения

Известные ограничения описаны в:

- [Current limitations](doc/src/content/docs/en/appendices/limits.md)
- [Текущие ограничения](doc/src/content/docs/ru/appendices/limits.md)

Разрабатываемый сервер 1.2 аутентифицирует catalog Principal по паролям с
Argon2id verifier. Plain TCP предназначен для доверенного host или защищенной
сети; direct TLS проверяет цепочку сертификатов и имя сервера и не допускает
plaintext downgrade на этом endpoint. Настроенный Argon2id verifier требует
исходный пароль `root` на каждом endpoint и отключает беспарольный вход. Без
verifier беспарольный `root` остаётся доступен только как восстановительный
путь через plaintext loopback listener. Следуйте
[руководству по аутентификации](doc/src/content/docs/ru/administration/authentication.md)
и выдавайте каждому Principal только необходимые права базы, схемы и объектов.
