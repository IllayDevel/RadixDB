Учебник предполагает сборочный компьютер Linux x86-64, оболочку Unix
и рабочую копию исходников RadixDB. Сервер базы данных не требуется.
Для других систем нужны собственные проверки сборки и файловой системы,
прежде чем считать эти инструкции проверенными на них.

## Сборка клиента

Установите инструментальную цепочку Rust из `rust-toolchain.toml`, включая
Cargo, а также системный компилятор C и компоновщик. Проверенные исходники
используют Rust 1.97.0. Cargo нужен доступ к реестру пакетов либо уже
заполненный кэш зависимостей. Из корня репозитория выполните:

```sh
cargo build --locked --bin radixdb-cli --features cli
./target/debug/radixdb-cli --version
export PATH="$PWD/target/debug:$PATH"
```

`--locked` запрещает сборке обновлять разрешение зависимостей.
Вывод версии включает версию приложения, коммит Git и дайджест lockfile.
Сохраняйте эти сведения при сообщении об ошибке. Руководство предназначено для
разрабатываемой RadixDB 1.2; внизу страницы целевая версия документации и версия
приложения показаны отдельно. При сравнении результата указывайте коммит Git.

Это неоптимизированная отладочная сборка, подходящая для учебника.
Она не является эталоном производительности. Упаковка релиза и установка
службы описываются далее в главе установки.

## Проверка клиента

```sh
radixdb-cli -d memory:// -e "SELECT 1"
```

Результат содержит одну строку со значением 1. Эта база существует только
в процессе и исчезает после завершения клиента. В следующей главе используется
файловая база, чтобы разные сеансы работали с одними данными.

Перейдите к [первой базе данных](../first-database/). Продолжайте в той же
оболочке, чтобы изменённый `PATH` оставался доступен.
